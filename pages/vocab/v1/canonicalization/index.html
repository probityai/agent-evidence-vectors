canonicalization

Term URI: https://w3id.org/agent-evidence/vocab/v1/canonicalization

Section: record_binding. Criticality: critical.

The rule that turns a record, or the object a digest names, into the bytes that are hashed or signed. A digest or signature without a declared canonicalization cannot be recomputed by a second party: two correct implementations that guess differently get different bytes and one of them reports a forgery that is not there. The two safe-integer profiles are different rules, not two spellings of one: jcs_safe_integer_v1 allows fractions and judges the parsed double, jcs_integer_only_v1 refuses any fraction or exponent. A verifier never substitutes one for the other, never reads plain rfc8785 as either, and never reads a refusal by a declared profile as a failure of the record under rfc8785.

Registered values

  • https://w3id.org/agent-evidence/vocab/v1/canonicalization#rfc8785: The JSON Canonicalization Scheme of RFC 8785, applied to the parsed value. Numbers are serialized from their IEEE 754 double, so two number tokens with the same nearest double give the same bytes.
  • https://w3id.org/agent-evidence/vocab/v1/canonicalization#jcs_safe_integer_v1: RFC 8785, plus one refusal applied to the parsed double: a number token whose nearest double is an integer of magnitude 2^53 or more is refused, whether the token was written as an integer, with a fraction or with an exponent. Fractions below that magnitude are allowed. Duplicate member names, lone surrogates and invalid UTF-8 are refused before parsing.
  • https://w3id.org/agent-evidence/vocab/v1/canonicalization#jcs_integer_only_v1: RFC 8785 restricted to integer numbers: every number token is an integer of magnitude below 2^53, written without a fraction or an exponent, and never -0 (RFC 8785 writes it as 0, a rewrite this profile refuses). Any other number token puts the object outside this profile, which is a refusal by declared profile and not a canonicalization failure. Duplicate member names, lone surrogates and invalid UTF-8 are refused before parsing.
  • https://w3id.org/agent-evidence/vocab/v1/canonicalization#cbor_deterministic: The deterministic encoding of RFC 8949 section 4.2.1: preferred serialization, definite lengths and map keys sorted by their encoded bytes.
  • https://w3id.org/agent-evidence/vocab/v1/canonicalization#raw: No canonicalization: the digest or signature covers the exact bytes as transmitted or stored, and a verifier must hold those exact bytes.
