\section{Reproducibility}
\label{sec:w3c-reproducibility}

The provenance appendix of the 16 October draft (\aevmsg{Oct}{0120}) holds Roel Schuurkes's results-to-inputs table, placed there by him (\aevmsg{Oct}{0162}) and corrected in \aevmsg{Oct}{0163}. This section gives each row's rerun command, the platforms it is rerun on, and the reruns people posted by hand.

\paragraph{One command per row.} Every row with a command reruns from its pins with \texttt{python rerun.py <row>}, and all of them with \texttt{python rerun.py --all}, in \url{https://github.com/probityai/agent-evidence-vectors/tree/main/interop/w3c-v01-appendix}. The harness fetches each commit by its full SHA and compares the checkout with the pin, fetches each list attachment and compares its sha256 with the posted digest, installs the interpreter and package versions the producer named, runs the posted command, and compares what comes out with the digests posted on the list. Nothing is adjusted to make a row match. Two rows have no posted command, in their owner's words: R10 is ``the measurements in 0038 and 0046; no single command'' and R15's checker is ``not stated in Sep/0080'' (\aevmsg{Oct}{0162}). For R10 the appendix adds \texttt{rows/r10\_minus\_zero.py}, which writes the one value with the Python and Go readers at v0.17.4 and v0.18.1 and compares the bytes with those posted in \aevmsg{Oct}{0038}; it is offered for the row, not substituted for the posted measurement. For R15 the appendix only tallies the census file's own state fields; the classifier behind them is not rerun.

\paragraph{Platforms and schedule.} A workflow in the same repository reruns every row with a command on each change to the appendix, on demand, and weekly (Mondays, 05:35 UTC), on three runners: Linux x86\_64 (\texttt{ubuntu-24.04}), Linux arm64 (\texttt{ubuntu-24.04-arm}) and macOS arm64 (\texttt{macos-15}). Each result file names the platform it ran on, and a pin that stops resolving upstream turns the run red.

\paragraph{What ``reproduced'' means here.} A row reproduces when every posted digest comes out of the rerun: byte-identical files, except files the producer said carry the runner or the environment, which are listed with that reason and still reported with both digests. These runs are an automated rerun from the pins, operated by the appendix's author. They are not reproductions in O8's sense, which in the group's use is ``the producer's implementation, run by another operator'' (\aevmsg{Oct}{0163}): for R1 and R9 the appendix's author is the producer, and for every row the expected outputs are in view. The reproductions in O8's sense are the reruns people posted, listed below and cited by message; the workflow repeats them on a schedule and does not replace them.
