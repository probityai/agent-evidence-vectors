\section{Verification}
\label{sec:w3c-verification}

Each v0.1 report in the table can be checked with one command, from an empty directory,
\begin{quote}
\texttt{uvx agent-evidence-vectors==\aevreadrelease{} --read-w3c-report <file>}
\end{quote}
\noindent which prints \texttt{conforms}, or one line per shape error or rejection row, and exits 0 when the report conforms, 1 when it does not, and 2 when the reader reached no verdict. Rows that are not reports (readers' verdicts, comparisons, census counts) are checked by their rerun command instead. The evidence classes are their authors' words: ``reproduction in O8's sense'' (\aevmsg{Oct}{0163}), ``a reader written from the 0087 text alone'' and ``proposed'' (\aevmsg{Oct}{0162}), ``the closest this paper comes to an independent record'' (\aevmsg{Oct}{0150}). The class of every cell this appendix runs is ``automated rerun from the pins, operated by the appendix's author''. Following \aevmsg{Oct}{0163}, units differ by row and no column is summed.

\paragraph{Every report under every reader.} The committed reader matrix retains the original R6 report and the separately re-encoded R6-v01 report (\aevmsg{Nov}{0006}) as different inputs. The generated table below lists the report and reader inventory, their stored verdicts and the per-reader negative-control totals directly from \texttt{matrix.json}. R6-v01 conforms in every stored reader cell; that does not change the original R6 outcomes: Python, Go and Rust reject, Rouiada Abbas's reader cannot read, and Lars Kersten Kroehl's reader cannot tell. The Python CLI result at \aevreadrelease{} reported in \aevmsg{Nov}{0010} is a separate observation, not another reader column in this matrix. R4's reports are rejected under W3C-R-020 by the older Python readers. The readers written from the text receive each report wrapped as a corpus member, through an adapter that writes \texttt{\{"id": <input>, "subject": <report>\}} and nothing else. R14 is a comparison of reader verdicts, not an independent reproduction of producer checks.

\paragraph{Reader availability in R9.} The release comparison uses Python and Go at v0.17.4; Rust is available from v0.18.0. It does not establish a Rust result at v0.17.4 (\aevmsg{Nov}{0010}).

\paragraph{Negative controls for the readers.} A reader that accepted everything could match the conforming base reports, so the matrix also records single-field negative controls. The generated controls table gives the denominator, outcomes and target-citation counts for each reader. Positive controls and targets marked not applicable are separate populations; neither belongs in that negative-control denominator. The positive controls use a non-ASCII check identity and a root recomputed over the RFC 8785 form. Their ASCII-escaped twins target W3C-R-020, the cause Kenne Ives gave for R4 (\aevmsg{Oct}{0150}). A declared moved that disagrees with the recomputed value targets W3C-R-021; a recomputed moved outside compared targets W3C-R-016.

The readers written from the text answer cannot-tell where the text leaves the reading open, as the reader of 0039 was built to (\aevmsg{Oct}{0039}). The generated target-population table retains the separate outcome classes, including positive controls. The older Python readers accept the ASCII-escaped W3C-R-020 twins and reject their RFC 8785 positive controls. For the text-derived readers, the shared numbered-row control not rejected is R1 with a qualifier on a non-verdict check, targeting row 6. Detailed cells are retained in the generated \texttt{matrix/matrix.md}. The command list gives ways to check the reports; it is not an additional set of recorded reader cells. Target cited counts whether the named target was cited, not merely whether a mutant was rejected. These are findings for their authors, not faults.
