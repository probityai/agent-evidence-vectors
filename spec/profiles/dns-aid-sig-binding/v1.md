# Profile `dns-aid-sig-binding/v1`

URI: `https://probityai.github.io/agent-evidence-vectors/profile/dns-aid-sig-binding/v1`

The reading rules a verifier applies to the `sig` SvcParam (key65405) of a DNS-AID discovery record:
a compact JWS whose payload binds the record's endpoint and, through `svcb`, its other DNS-AID
parameters. Two verifiers that apply this profile to the same record, JWKS, instant and key authority
reach the same verdict. A verdict names the profile it applied by this URI.

## Rules

1. **Encoding.** The JWS is three parts of strict, canonical, unpadded base64url (RFC 7515 section 2,
   RFC 4648 section 5). A part with a character outside the URL-safe alphabet, with padding, or with
   non-zero trailing bits is refused. A lenient decoder reads the same bytes from the non-canonical
   form and the signature still verifies, so only a canonical-form check refuses it.
2. **I-JSON.** Header and payload are I-JSON objects (RFC 7493). A repeated member name is refused,
   so a first-wins reader and a last-wins reader cannot bind two values of `fqdn` to one signature.
3. **Header.** `crit` is refused (RFC 7515 section 4.1.11: the reader understands no extension).
   `alg` is `ES256` and the signature is 64 bytes. Any other `alg` is refused, even when an ES256
   signature over the same bytes verifies.
4. **Integers.** `port`, `iat` and `exp` are JSON integers; `443.0` is refused.
5. **Window.** The record is expired when `exp` is at or before the instant, and not yet valid when
   `iat` is more than 300 seconds after it. The instant is the consumer's, never the record's.
6. **Endpoint.** `fqdn` and `target` equal the served record's, compared as DNS names (ASCII case
   and a trailing dot ignored), and `port` equals exactly. The payload's `alpn` equals the record's
   `proto` when it carries one (draft-dawn-dnsaid-00 Table 1: `alpn` names the transport and `proto`
   the agent protocol), and the record's `alpn` otherwise.
7. **Parameters.** When the payload carries `svcb`, it equals the unpadded base64url SHA-256 of
   `svcb1:` followed by the RFC 8785 form of the present DNS-AID parameters (`cap`, `cap-sha256`,
   `bap`, `policy`, `realm`, `connect-class`, `connect-meta`, `enroll-uri`, `well-known`). An empty
   value is a value; only an absent parameter is left out. A payload without `svcb` attests the
   endpoint only: `signature_coverage` is `endpoint_only`, never `full`.
8. **Key source.** A JWKS URL on any host other than `dns-aid.<zone>` or the zone apex is refused.
9. **Key authority.** A signature that verifies under the key the evidence carries is not agreement.
   The verdict agrees only when a key authority the consumer names (vocabulary term `key_authority`:
   `pin`, `dnssec_chain` or `kt_inclusion`) authorises the verifying key for the record's zone. Under
   `none` the verdict is cannot tell. A `kt_inclusion` authority reads a statement of type
   [`predicate/v1/key-set-inclusion`](../../predicates/key-set-inclusion.md).
10. **Verdicts.** Every malformed record, signature or JWKS input yields a verdict, never an
    exception. Every verdict states the key-set fingerprint of the JWKS it read and its
    `signature_coverage` value.

## Conformance

An implementation conforms when it gives the expected verdict for every case of
`corpora/vectors-dns-aid-sig-v01/`. The reference reader is agent-evidence-verify's `dns_aid_sig/v1`
claim type (probityai/probity, `packages/agent-evidence-verify`), which names this URI in every
decision's scope.
