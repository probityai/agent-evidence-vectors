# vectors-agent-payment-mandate

Cases for `agent-payment-mandate/v1`: a dispute evidence pack for an agent-initiated payment, judged from its own record.

The expected decision and reason for every case are in `MANIFEST.json`; `INDEX.md` and `profile.json` are generated by `gen_vectors.py`.

The pack binds four things: the mandate the user signed (an AP2 cart or intent mandate, a Mastercard Verifiable Intent credential or a Stripe Shared Payment Token, each named by concept), the credential the agent presented, the charge that ran, and the receipt that ties them. The reader recomputes the mandate digest and the execution digest instead of trusting the fields that claim them.

For: payment service providers, acquirers and agent-wallet vendors that need to hand an issuer or arbitrator a replayable record of an agent's purchase.

## Run it

```bash
pip install agent-evidence-vectors
python vectors-agent-payment-mandate/check_vectors.py
```

The command prints `answered N of N cases`. To judge the cases with your own verifier, name it: `check_vectors.py --verifier "/path/to/verifier"`. It is run as `<verifier> <case-dir>/case.json --json`, prints one JSON object with `decision` and `reason`, and exits 0 for `accepted` and 1 for `rejected`.

## Cases

| Case | Expected | What it is |
| --- | --- | --- |
| authorized-ap2-cart | accepted, `mandate_chain_holds` | cart mandate, bound credential, in-limit charge, fulfilment recorded |
| authorized-vi-credential | accepted, `mandate_chain_holds` | verifiable-intent credential bound to its intent, charge inside the ceiling |
| authorized-spt-seller-bound | accepted, `mandate_chain_holds` | seller-bound shared token used once at its seller inside its bounds |
| authorized-at-exact-limit | accepted, `mandate_chain_holds` | charge equal to the ceiling is inside the mandate |
| mandate-unsigned | rejected, `mandate_unsigned` | the mandate carries no issuer signature |
| mandate-terms-edited | rejected, `mandate_digest_mismatch` | terms raised after the digest was taken |
| credential-bound-to-another-mandate | rejected, `credential_not_bound_to_mandate` | the credential names a different mandate digest |
| charge-after-expiry | rejected, `mandate_expired` | executed after the mandate expired |
| charge-over-limit | rejected, `amount_over_limit` | one minor unit over the authorised ceiling |
| charge-in-other-currency | rejected, `currency_mismatch` | authorised in EUR, charged in GBP |
| charge-at-other-merchant | rejected, `merchant_mismatch` | token scoped to one seller, used at another |
| executed-token-differs | rejected, `token_not_the_executed_token` | the charge ran under a token the credential does not hold |
| single-use-token-replayed | rejected, `single_use_token_replayed` | a single-use token already consumed is used again |
| receipt-not-over-execution | rejected, `receipt_not_bound_to_execution` | execution changed after the receipt digest was taken |
| post-checkout-fulfilment-missing | rejected, `post_checkout_action_missing` | capture recorded, the fulfilment action is missing |

Each rejected case is one mutation away from the accepted case it names as its twin, and the rule it names is the first that fires.

## The checker is held to its rules

`mutation_check.py` switches each rule off alone and requires that at least one rejected case then gets a different answer. The tests run each rule-less verifier, a mutant, through the contract and require the corpus to refuse it: 11 rules, 11 mutants, every one caught.

## Pin it in your CI

```yaml
- run: pip install agent-evidence-vectors==X.Y.Z
- run: python -m agent_evidence_vectors.paymentmandate --verifier "your-verifier"
```

Pin the exact version; conformant means passing that version's cases.

## What it does not test

It does not vendor or quote any of the three schemes' texts, names no upstream field, and does not say who bears the loss in a dispute. `profile.json` maps each scheme's concept to the receipt-side field checked. It proves a charge stayed inside what a user authorised; it does not prove the user meant it.
