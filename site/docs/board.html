Conformance board

Every outside implementation we can run, scored against one pinned corpus

Generated from the board data; corpus agent-evidence-vectors 0.29.3, results of 2026-10-29.

Each row runs an outside implementation’s own code on the saved records of agent-evidence-vectors 0.29.3. Our CI re-runs every score on a schedule and whenever the implementation’s default branch moves, so a verdict at a new upstream commit appears here without anyone asking for it. Pass means the harness executed every vector and none failed. Fail means it executed every vector and some failed. Not runnable means the implementation could not be run to completion on that corpus, and the cell says why.

A verdict is kept only when the same adapter first passes two controls: the corpus’s reference canonicalizer must pass every vector, and a deliberately wrong canonicalizer must fail the ten vectors the corpus expects it to fail. For the anchor stream the control is that the runner reproduces the corpus’s own recording of a published verifier tag on every member. A failure in a row below therefore comes from the implementation, not from the adapter or the harness. Each implementation’s declared scope is printed beside its verdict. A vector outside the scope an implementation declares is a difference of profile, and the row says so rather than hiding it.

Verified by Probity

Verified by Probity (github.com/probityai/probity). A score on this board is our CI running an outside implementation against the pinned corpus. It is not the badge. The badge is granted to a project, never self-declared, recorded in the grant ledger of agent-evidence-vectors, and re-checked at every release; the rules are on the Verified by Probity page. No row on this board carries it.

To run the same corpus in your own CI, pin the package:

uv add agent-evidence-vectors==0.29.3
pip install agent-evidence-vectors==0.29.3

Add an implementation

Add one entry to data/board.toml: the repository, a pinned commit, the file and function that take the corpus, and its declared scope. The workflow scores it on the next run. To run one row by hand, see tools/run_board.py. The packaged corpus runs in your own CI with the agent-evidence-vectors Action.
